# HANA STUDIO — Inspiration, Homage & Source Policy

HANA should be openly inspired by the real world while remaining unmistakably its own IP.

## Three inspiration lanes

### 1. Living artists, scientists, designers, activists and creators
Default treatment: inspiration source, not fictional character.

Allowed workflow:
- study the real person's ideas/work
- record the source
- identify the underlying principle that inspires us
- transform that principle into an original HANA person/place/object/mechanic
- credit the inspiration in internal/public notes when appropriate

Do not use without explicit review/permission:
- name as a commercial character
- recognizable likeness
- implied endorsement
- copied signature style presented as if by that creator
- quotes beyond lawful/appropriate quotation
- private biography as story material

Partnership route:
If we truly want the actual living person in HANA, treat it as a collaboration/licensing conversation, not a shortcut.

### 2. Historical people / public-domain sources
Potentially usable more directly, but still require:
- rights/status review by jurisdiction
- source citation
- distinction between historical fact and HANA fiction
- no misleading endorsement
- respect for descendants/communities where relevant

Prefer interpretation over cosplay.

### 3. Myths, legends, folklore and religious/cultural traditions
Public-domain does not mean context-free.

Before use:
- identify culture, region and source tradition
- determine whether the figure/practice is sacred or still actively practiced
- consult primary/credible cultural sources
- avoid flattening several traditions into one “exotic” aesthetic
- use sensitivity review for living traditions
- clearly mark HANA reinterpretation

## Source Register fields

Every inspiration entry should store:
- source_id
- source_type
- person/work/tradition
- creator / culture / institution
- country / region
- date / era
- source URL / publication
- exact principle that inspired HANA
- what we transformed
- HANA asset/card/character using the inspiration
- rights_status: green / review / permission-required
- attribution_text
- reviewer
- reviewed_at

## Creative rule

We are not building a museum of references.

A successful homage should still work if the player has never heard of the source.

The source adds depth; it should not substitute for character.

## Quote policy

HANA card flavor text should default to original writing.

If a real-world quote is ever used:
- verify the quote
- verify source/publication
- verify rights/context
- use only when it meaningfully improves the work
- attribute clearly
- do not imply the speaker endorses HANA

Original in-world lines are preferred.
